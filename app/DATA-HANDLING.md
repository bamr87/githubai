# What the hosted relay stores

This is the factual inventory of data the GitHubAI relay holds, why each item exists, and how long it lives. It is written to be verifiable against the code — [`relay/schema.sql`](relay/schema.sql) is the complete schema, and [`relay/src/store.js`](relay/src/store.js) contains every statement that touches it. A published Marketplace listing needs a privacy policy; this document is the accurate technical basis for one, not a substitute for legal review.

## Never stored

- **Repository code.** The relay never clones, checks out, or reads source files, with one exception it names explicitly: the org policy file at `.github/githubai-org.yml` in your own `.github` repository.
- **Issue and pull request content.** Titles, bodies, comments, and diffs are not read, forwarded, or retained. The relay reads issue and PR *numbers*, labels, draft state, and author type — the fields it needs to decide where to route — and nothing else.
- **Your Claude Code OAuth token or Anthropic API key.** These live only as Actions secrets in your repositories and organization. The relay has no access to them and no mechanism to receive them.
- **GitHub user access tokens.** Dashboard sign-in exchanges an OAuth code for a user token, uses it to read your login and installation ids, then discards it. It is never written to the database or into a cookie.
- **Model traffic.** No prompt, completion, or model API call passes through this service. Claude runs in your Actions.

## Stored

| Data | Why | Retention |
|------|-----|-----------|
| Installation id, account login and type, repository selection, suspension state | Identify the tenant and know whether to route at all | Until the App is uninstalled |
| Repository full names covered by the installation | Show coverage on the dashboard; learned from installation events and observed traffic | Until uninstall or removal from the installation |
| Marketplace plan name | Plan-dependent limits | Until uninstall |
| Cached org policy document, its source path, last fetch time, and last parse error | Apply org routing rules without re-reading the file on every event | Overwritten on refresh; deleted on uninstall |
| Activity rows: timestamp, repository name, event name and action, issue/PR number, dispatch type, outcome, and a short reason string | Answer "why did (or didn't) automation run" — the core operational question a router owes its users | 30 days, then deleted by a nightly job |
| Webhook delivery ids | Prevent a redelivered webhook from dispatching twice | 30 days |
| Per-installation dispatch counter for the current minute | Rate limiting | Overwritten each minute |

Activity `detail` strings are generated by the relay itself (for example `claude:skip label present`, `org policy disables automation.auto_merge`, `dispatch githubai-review to acme/api failed: 403`). They can include a repository name and a GitHub error message; they never include issue or PR text.

## Credentials the relay holds

The App's private key and webhook secret, as Cloudflare Worker secrets. Installation tokens are minted per request, cached in memory for under an hour, and never persisted. Dashboard sessions are HMAC-signed cookies containing a login and a list of installation ids — no token, and unreadable without the signing secret.

## Deletion

Uninstalling the GitHub App immediately deletes the installation record, its repository list, its cached policy, and its rate-limit counter. Activity rows and delivery ids age out within 30 days; an operator can purge them on request with a single statement (see [OPERATIONS.md](OPERATIONS.md#retention-and-deletion)).

## Self-hosting

Everything above describes a deployment of this code. Self-hosters run the same Worker in their own Cloudflare account, so the data never leaves their infrastructure and this document describes what *they* hold.
